# 표준물류단가 산정 시스템 — 설계·가정 문서

> TPL(3자물류) 영업팀이 신규 화주 견적을 낼 때, **화주 데이터(출고내역·상품·재고)를 표준 양식으로 업로드하면
> 물동 프로파일을 자동 추출하고, 자사 원가 마스터와 결합해 작업비·보관비·배송비 단가를 산정**하는 도구.
> 이 문서는 계산에 들어가는 **모든 가정·수식·한계·필요조건**을 기록한다. 숫자 하나라도 "왜 이 값인가"를
> 물었을 때 이 문서로 답할 수 있어야 한다.

- 작성: 2026-09-02, Claude + HanEx
- 코드: `engine.py`(산정 엔진) · `profile.py`(데이터 추출) — 이 문서의 수식 번호가 코드 주석에 대응됨

---

## 1. 목적과 범위

### 1.1 하는 것
- 화주가 제공하는 **실적 데이터**(출고내역, 상품마스터, 재고/입고)에서 견적에 필요한 값을 **추출**
- 자사 **원가 마스터**(인건비·생산성·창고·배송단가표)와 결합해 **원가 기반 단가** 산정
- 항목별 견적 단가표(입고비/출고비/보관비/배송비) + 민감도 시나리오 + 엑셀 견적서 출력

### 1.2 하지 않는 것 (범위 제외)
- **B2C 택배 요율** — 택배사 계약단가는 별도 협상 영역
- **냉장·냉동, 위험물, 대형(가구/가전) 특수화물** — 원가 구조가 달라 표준 모델로 산정 불가
- **차량 운행원가 기반 배송비 자체 계산** — 배송비는 ①직접입력 ②권역 단가표 적용 ③배송비단가시스템(delivery_pricing) 연동 3가지만 지원 (운행원가 모델은 정책상 만들지 않음)
- **법적/세무 검토** — 산출 단가는 부가세 별도 원가 견적이며 계약단가가 아님

## 3. 데이터에서 추출하는 값 (물동 프로파일)

업로드 즉시 아래 값을 자동 계산해 화면에 보여주고, **모든 값은 수동으로 덮어쓸 수 있다**
(추출값 ≠ 확정값. 화주가 "내년엔 물량 2배"라고 하면 사람이 고쳐야 한다).

| 추출값 | 계산 | 용도 |
|---|---|---|
| 분석기간·영업일수 | 출고일자 min~max, distinct 일자 수 | 일평균 분모 |
| 월평균 출고 BOX | 총 BOX ÷ 개월수(영업일 기준 21.7일/월 환산) | 견적 기준 물동 |
| 일평균 출고 BOX/PLT | 총량 ÷ 영업일수 | 인력 산정 |
| **피크일 물동** | 일별 BOX 상위 P95 (최댓값이 아닌 95백분위 — 이상치 1일에 인력을 맞추지 않음) | 피크 인력 |
| 피크배율 | P95 ÷ 일평균 | 고정/일용 인력 믹스 |
| 일평균 주문수·주문당 BOX | 주문번호 기준 (없으면 일자+배송처) | 피킹 난이도 참고 |
| 주문당 라인수 | 주문번호+상품코드 distinct | 피킹 방식(케이스/낱개) 판단 참고 |
| PLT 환산량 | Σ(박스수 ÷ PLT입수), 미매칭 상품은 A7 대표값 | 보관·상하차 산정 |
| PLT입수 커버리지 | 상품마스터 매칭 BOX 비율(%) | 신뢰도 표시 (80% 미만 경고) |
| 평균재고 PLT | 재고 업로드 시 일별 스냅샷 평균, 없으면 일평균출고PLT × 회전일수(A8) | 보관비 |
| 권역별 BOX 분포 | 주소 → 시도/시군구 파싱 (delivery_pricing과 동일 파서) | 배송비 모드② |
| 요일 편중 | 요일별 BOX 비중 | 참고 지표 |

## 5. 계산 로직 (수식)

### 5.1 작업비 (원/BOX)
공정 p의 단위당 원가:
```
C_p = 실부담시급_p ÷ 생산성_p            [원/단위]
박스당 환산: 단위가 PLT면 C_p ÷ PLT입수(가중평균), BOX면 그대로
```
- **입고계 공정**(하차·적치)은 입고 물동(A9) 기준, **출고계 공정**(피킹·검수·상차)은 출고 물동 기준
- 직접작업비 합 D = Σ C_p(박스당)
- 인력 소요 검증(참고 표시): 일 필요 인시_p = 일물동_p ÷ 생산성_p → 필요인원 = Σ인시 ÷ 8h.
  피크일은 P95 물동으로 재계산해 "평시 n명 + 피크 m명" 형태로 표기
- 소모품(A22) 가산 → 작업비 = D × (1+간접배부율 A21) + 소모품(박스당)

### 5.2 보관비
```
월 창고원가(화주 귀속) = (임차료 + 관리비) × 필요평수 + 장비비 배부 + 파렛트비
필요평수 = 평균재고PLT ÷ (평당적재 A14 × 가동률 A15)
PLT·월 단가 = (평당 임차료+관리비) ÷ (평당적재 × 가동률) + 파렛트 A25
박스당 배부(참고) = 월 보관비 ÷ 월 출고 BOX
```
- 가동률로 나누는 이유: 통로·리로케이션·계절 여유분의 빈 자리도 원가이기 때문

### 5.3 배송비 (원/BOX)
- 모드①: 입력값 그대로
- 모드②: Σ(권역별 BOX비중 × 권역단가) — 주소 파싱은 delivery_pricing과 동일한 시도 정규화 사용
- 모드③: delivery_pricing 연동(브리지) — min/max 박스당 단가 수신
- 모드②는 "단가표 적용"이며 운행원가 계산이 아님 (§1.2)

### 5.4 최종 견적단가
```
원가합(박스당) = 작업비 + 보관비(박스당 배부) + 배송비
견적단가 = 원가합 × (1 + 일반관리비 A23) ÷ (1 − 목표이익률 A24)
```
항목별 견적서에는 같은 배율을 각 항목에 적용해 **입고비(원/PLT)·출고비(원/BOX)·보관비(원/PLT·월)·배송비(원/BOX)**로 분해 표기.

### 5.5 민감도 (자동 산출 시나리오)
| 시나리오 | 변화 |
|---|---|
| 물동 −20% / +20% | 고정비(보관·고정인력) 배부 단가 변화 확인 |
| 생산성 −10% | 실측이 표준 미달일 위험 |
| 재고 +30% | 화주 재고 정책 변화 |
| 가동률 70% | 초기 램프업 기간 |

## 6. 한계성 (이 도구가 틀릴 수 있는 지점)

1. **과거 실적 기반** — 실적이 미래를 대표한다는 가정. 신규 런칭·프로모션·계절성(분석기간이 비수기면 과소)을 반영하지 못한다. → 3.의 추출값을 수동 보정하는 것이 운영 절차다.
2. **표준 생산성의 불확실성** — 상품 특성(중량물·혼적), 오더 밀도, 센터 레이아웃에 따라 ±30% 이상 흔들린다. 실측 전 견적은 반드시 min/max 범위로 제시할 것.
3. **PLT입수 커버리지** — 상품마스터 미매칭 물량은 대표값 추정(A7)이라 보관·상하차비 오차의 주원인. 커버리지 80% 미만이면 화면에 경고.
4. **주문 구조 미반영 영역** — 낱개(EA) 피킹, 유통기한/로트 관리, 반품 재작업은 표준 공정에 없다. 필요 시 공정 마스터에 수동 추가해야 한다.
5. **배송비 모드②의 한계** — 시도 단위 평균 단가라 시군구·점포밀도 차이를 뭉갠다. 정밀 산정은 모드③(delivery_pricing)으로.
6. **고정비 배부의 순환성** — 단가는 물동을 전제로 하는데 물동이 줄면 단가가 올라간다. 계약서에 **최소 물동 보장(MOQ) 또는 물동 구간별 단가**를 넣는 근거로 민감도 표를 사용할 것.
7. **세금·보험·감가 단순화** — 화재보험, 재고자산 보험, 시스템(WMS) 라이선스는 간접배부율(A21)에 뭉뚱그려져 있다. 큰 화주는 별도 계상 권장.

## 7. 필요조건 (견적 확정 전 체크리스트)

- [ ] 출고내역 3개월 이상 (최소 1개월) — 기간이 짧으면 계절성 확인 불가
- [ ] 상품마스터 PLT입수 커버리지 80% 이상
- [ ] 재고 스냅샷 확보 (없으면 회전일수 가정을 화주와 합의)
- [ ] 생산성·시급을 현장 실측/최신 단가로 교체
- [ ] 창고 임차료·평당적재를 대상 센터 실값으로 교체
- [ ] 배송비 모드 선택 및 근거 확인
- [ ] 민감도 표를 근거로 최소물동/구간단가 조건 검토
- [ ] 산출 결과의 "가정 요약"을 견적서에 첨부 (도구가 자동 생성)

## 8. 산출물

- 화면: 물동 프로파일 → 원가 브레이크다운(공정별) → 항목별 견적 단가카드 → 민감도 표
- 엑셀 견적서: ①견적 요약(항목별 단가) ②원가 상세 ③적용 가정 전체 목록 ④물동 프로파일
- 모든 견적은 저장되어 목록에서 재열람·복제 가능
